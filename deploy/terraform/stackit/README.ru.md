# OpenConstructionERP в STACKIT: отдельный изолированный экземпляр для каждой компании

[English](README.md) | [Deutsch](README.de.md) | Русский

Модули Terraform, которые запускают OpenConstructionERP в немецком облаке
[STACKIT](https://www.stackit.de) с **отдельным экземпляром для каждой компании**: собственный
сервер базы данных, собственный бакет, собственные учётные данные и собственное пространство имён.
Данные остаются в немецких центрах обработки данных (регион `eu01`).

```
deploy/terraform/stackit/
  modules/platform/   общий слой: кластер SKE, ingress-nginx, cert-manager, при желании зона DNS и Observability
  modules/company/    одна компания: PostgreSQL Flex, бакет, пространство имён, приложение, TLS-ingress, запись DNS
  examples/two-companies/   готовый пример: одна боевая и одна песочница
```

## Что создаётся для каждой компании

| Ресурс | Назначение |
|---|---|
| Экземпляр PostgreSQL Flex, пользователь, база | Собственный сервер БД компании. Подключаться могут только исходящие адреса кластера (ACL). Ежедневные резервные копии, хранение от 32 до 90 дней |
| Бакет Object Storage, группа учётных данных, учётные данные | Свой бакет и свои ключи для файлов BIM/CAD и документов |
| Пространство имён Kubernetes `oce-<slug>` | Граница изоляции с метками компании и режима |
| ResourceQuota и LimitRange | Компания не может отнять ресурсы у соседей |
| NetworkPolicy | Входящий трафик только от ingress-контроллера; исходящий только к DNS и в публичный интернет, никогда в другие пространства имён и сеть узлов |
| Secret `oce-env` | URL базы, секрет JWT, ключи S3, при необходимости пароль SMTP и токен Model Serving |
| ConfigMap `oce-config` | Все несекретные настройки |
| PersistentVolumeClaim `oce-data` | Каталог `/data` (около 20 модулей пишут туда даже при хранилище S3) |
| Deployment (1 реплика, `Recreate`) | Приложение, закреплённое за точной версией образа |
| Service и Ingress | Публичный HTTPS с сертификатом Let's Encrypt, загрузки до 512 МБ |
| Запись DNS A | `<slug>.<base_domain>` на адрес ingress (необязательно) |
| Токен AI Model Serving | Необязательно, подготовлено для дорожной карты (см. ниже) |

Общее на всех: кластер SKE, ingress-nginx, cert-manager и необязательный экземпляр Observability.

## Требования

- Проект STACKIT и **ключ сервисного аккаунта** (JSON) с правами на создание перечисленных ресурсов.
- В проекте **включён Object Storage** (один раз, в портале STACKIT).
- Домен, который можно делегировать в STACKIT DNS, либо существующая зона STACKIT DNS. Без
  автоматизации DNS задайте `zone_id = null` и создайте записи A самостоятельно.
- Terraform 1.7 или новее (CI использует 1.9) и доступ к `ghcr.io`.
- Идентификатор flavor для PostgreSQL Flex: `stackit postgresflex flavor list`.

## Быстрый старт

```bash
cd deploy/terraform/stackit/examples/two-companies
export STACKIT_SERVICE_ACCOUNT_KEY_PATH=/путь/к/key.json
cp terraform.tfvars.example terraform.tfvars        # укажите проект, домен, flavor, компании
terraform init
terraform apply -target=module.platform             # кластер, ingress, сертификаты (только первый запуск)
terraform apply                                     # базы, бакеты и сами компании
```

`terraform output urls` покажет адреса. **Откройте адрес и зарегистрируйтесь: первый
зарегистрированный пользователь становится администратором** этого экземпляра. Дальнейшая
регистрация подчиняется `registration_mode` (по умолчанию `admin-approve`).

Первый запуск экземпляра создаёт около 600 таблиц и занимает несколько минут; проба запуска ждёт до
15 минут.

Перед реальным использованием перенесите состояние в удалённый бэкенд, см.
`examples/two-companies/backend.tf.example`. Состояние содержит пароли баз и ключи хранилища в
открытом виде, поэтому держите его закрытым и зашифрованным. Бэкенд PostgreSQL (`pg`) даёт блокировку
состояния; бэкенд S3 в STACKIT Object Storage работает, но без блокировок.

## Добавление компании

Добавьте запись в карту `companies` и примените:

```hcl
companies = {
  acme   = { display_name = "Acme Construction GmbH" }
  bauer  = { display_name = "Bauer Hochbau", custom_hostname = "erp.bauer.example" }
}
```

Новая компания получает новую базу, бакет и пространство имён; существующие компании не
затрагиваются. Если `custom_hostname` лежит вне вашей зоны, клиент сам создаёт запись DNS (A на адрес
ingress); тогда задайте `create_dns_record = false`.

## Из песочницы в продакшен

У песочницы (`mode = "sandbox"`) есть демоданные (`SEED_DEMO=true`), меньшие размеры и метка
`oce/expires=<дата>` на всех объектах (по умолчанию 30 дней, `sandbox_days`). Метка только
информирует: **ничего не удаляется автоматически**. Чтобы получить боевую компанию из песочницы,
создайте новую боевую запись; демоданные не переносятся, поэтому песочница нужна для пробы. Не
помещайте в песочницу реальные данные проектов.

## Удаление компании

1. Удалите запись из карты. Terraform уничтожит пространство имён, базу и бакет.
2. Бакет, в котором остались объекты, **нельзя удалить**. Сначала очистите его (портал STACKIT или
   любой S3-инструмент с ключами компании из `terraform output`), затем примените снова.
3. Удаление экземпляра PostgreSQL удаляет и его резервные копии. Заранее выгрузите нужное.

## Размеры

| | Песочница | Продакшен |
|---|---|---|
| Память приложения, запрос / лимит | 1 ГиБ / 2 ГиБ | 1 ГиБ / 3 ГиБ |
| CPU приложения, запрос | 500m | 500m |
| Том `/data` | 10 ГБ | 50 ГБ |
| Хранилище PostgreSQL | 10 ГБ | 50 ГБ |
| Хранение резервных копий | 32 дня | 35 дней |
| Нужная ёмкость узла | около 0,5 vCPU, 1 ГиБ | около 0,5 vCPU, 1 ГиБ, пик до 3 ГиБ |

Любое значение можно переопределить для компании. Узел 4 vCPU / 8 ГиБ вмещает около трёх компаний.
Увеличивайте `minimum`/`maximum` в `node_pools` по мере роста. Flavor PostgreSQL
(`postgres_flavor_id`) выбирайте по размеру компании; начните с малого, позже его можно сменить.

## Заметки по безопасности

- **Изоляция на каждую компанию:** своё пространство имён с NetworkPolicy, свой экземпляр PostgreSQL
  (отдельный сервер, а не только отдельная схема), свой бакет, свои учётные данные, свой секрет JWT.
- База принимает подключения только с исходящих адресов кластера, приложение подключается с
  включённым TLS.
- Секреты хранятся в Kubernetes Secret (base64, сам Kubernetes их не шифрует) и в состоянии
  Terraform. Шифруйте состояние на диске и ограничьте доступ к нему и к кластеру.
- Ограничьте `api_allowed_cidrs` (ACL API Kubernetes) адресами офиса или CI.
- Контейнер работает не от root, все capabilities сброшены, профиль seccomp RuntimeDefault.
- Секрет JWT создаётся один раз для компании и остаётся неизменным; не удаляйте его из состояния,
  иначе все сессии завершатся.
- Версии образа закреплены (`latest` отклоняется). Обновление: смените `image_tag` и примените.

## Почему одна реплика и стратегия `Recreate`

При запуске создаётся схема, работает самолечащийся мигратор (под защитой advisory-блокировки базы) и
без блокировки проставляется состояние миграций. Два одновременно стартующих экземпляра, как при
rolling update, могли бы столкнуться. Том `/data` к тому же `ReadWriteOnce`: он подключается только к
одному узлу. Поэтому модуль запускает ровно одну реплику и заменяет её через `Recreate`: старый под
останавливается, затем стартует новый. Обновление означает короткий простой (после первого запуска
обычно меньше минуты). Redis и Qdrant не разворачиваются: исполнитель задач работает внутри процесса,
а в образе есть встроенное векторное хранилище в `/data/vectors`.

## Дорожная карта, в этой версии нет

- Единый вход OIDC для входа в компании.
- AI Model Serving в приложении: модуль может создать токен и кладёт `STACKIT_MODEL_SERVING_TOKEN` и
  `STACKIT_MODEL_SERVING_BASE_URL` в секрет компании. Приложение пока не читает из окружения базовый
  URL, совместимый с OpenAI (пакет 4 дорожной карты).
- Команда резервного копирования и экспорта целой компании (дамп базы, бакет и `/data`).
- Необязательное задание миграции перед запуском (сейчас приложение мигрирует себя при старте).

## Проверить перед первым применением

Модули написаны по документации провайдера без доступа к аккаунту STACKIT. CI проверяет формат,
корректность схемы и логику на имитированных провайдерах; следующее она подтвердить не может.
Проверьте при первом запуске (`terraform validate` и `plan` укажут на большую часть):

1. `stackit_postgresflex_instance`: имена атрибутов `flavor_id`, `network.acl`, `storage`,
   `retention_days` и путь вывода `connection_info.write.host` / `.port`.
2. PostgreSQL Flex: допустимая длина имени экземпляра (имена `oce-<slug>`, до 24 символов),
   минимальный размер хранилища, требует ли сервер TLS (`?ssl=require` включён по умолчанию;
   `database_ssl = false` только если соединение не проходит из-за этого) и могут ли пользователи с
   ролями `login` и `createdb` создать все таблицы.
3. Параметр запроса `ssl=require` и имя переменной `DATABASE_SYNC_URL` в вашей версии образа
   (настройки читают `database_sync_url`).
4. SKE: тип машины `c1.4` и зона `eu01-1` существуют в вашем проекте (измените `node_pools`),
   `kubernetes_version_min`, и принимает ли блок расширения `observability` поле `instance_id`.
5. Kubeconfig SKE: модуль ожидает в созданном kubeconfig данные клиентского сертификата
   (`client-certificate-data`). Если STACKIT отдаёт конфигурацию на основе OIDC или токена, измените
   `providers.tf`.
6. `egress_address_ranges` это адрес, который база видит на самом деле. Если поды достигают базы
   другим путём, расширьте `postgres_allowed_cidrs`.
7. Сервис типа `LoadBalancer` получает публичный адрес в STACKIT без дополнительных аннотаций
   (ожидаемо, не подтверждено), а IP клиентов доходят до приложения через `X-Forwarded-For`
   (`externalTrafficPolicy` по умолчанию `Cluster`, поэтому приложение может видеть адреса узлов).
8. Значение `TRUSTED_PROXIES` по умолчанию покрывает обычные диапазоны подов и узлов (`10.0.0.0/8`,
   `100.64.0.0/10`, ...). Убедитесь, что CIDR подов вашего кластера входит в него.
9. Числовой ID пользователя контейнера: пользователь образа `oe` системный; `run_as_uid` по
   умолчанию 999. Проверка: `docker run --rm --entrypoint id ghcr.io/datadrivenconstruction/openconstructionerp:<tag>`.
10. Формат имени набора записей DNS (используется полное имя с точкой в конце) и TTL.
11. Object Storage: правила имён и уникальность бакета (`oce-<slug>-data`), не нужны ли учётным
    данным дополнительные права, и конечная точка S3 `https://object.storage.eu01.onstackit.cloud`
    с доступом в стиле path в S3-клиенте приложения.
12. AI Model Serving: `stackit_modelserving_token` в некоторых версиях провайдера может требовать
    флаг эксперимента; токен создаётся только при `enable_model_serving = true`.
13. Закреплённые версии чартов (ingress-nginx 4.11.3, cert-manager v1.15.3) и репозиторий чарта
    ingress-nginx доступны из кластера. Песочница с `SEED_DEMO=true` при `APP_ENV=production`:
    проверьте, что демо-учётные записи создаются ожидаемо в вашей версии образа.
14. Первый `terraform apply -target=module.platform` нужен, потому что провайдеры Kubernetes и Helm
    настраиваются по кластеру, которого ещё нет.

## Стоимость

Вы платите за рабочие узлы SKE, на каждую компанию за один экземпляр PostgreSQL Flex и один бакет, за
LoadBalancer и при желании за Observability. Платформенный слой общий, поэтому дополнительная
компания стоит в основном как её экземпляр PostgreSQL плюс доля узла.
