# Передача пользователей по SCIM 2.0

Подключите провайдера удостоверений (IdP) один раз. После этого люди появляются в OpenConstructionERP, меняют роль вместе с группой и теряют доступ, когда уходят из компании.

## Настройка

1. Войдите как администратор и откройте **Настройки > Identity**.
2. Скопируйте **базовый URL SCIM** (`https://<ваш-хост>/scim/v2`).
3. Нажмите **Создать токен**. Токен это API-ключ с областью `scim`, привязанный к вам. Он показывается один раз и нужен только в IdP.
4. Вставьте оба значения в IdP:
   - **Microsoft Entra ID**: корпоративное приложение, подготовка, режим «Автоматически». URL клиента = базовый URL, секретный токен = токен. Проверьте подключение и запустите подготовку. Сопоставьте `userPrincipalName` с `userName`, `objectId` с `externalId`.
   - **Okta**: приложение, Provisioning, SCIM-коннектор. Базовый URL, уникальное поле `userName`, аутентификация HTTP-заголовком (bearer-токен). Включите создание, обновление и деактивацию пользователей.
   - **Keycloak**: встроенного SCIM-клиента нет. Используйте расширение SCIM-провижининга с тем же URL и токеном.
5. Передайте группы из IdP. В **Настройки > Identity** выберите роль для каждой группы, которая должна её давать. Группы без роли только подписи.

## Что может и чего не может IdP

- Создавать, изменять и удалять пользователей и группы, менять состав групп. Повторное создание безопасно: поиск идёт по `externalId`, затем по email, существующая локальная учётная запись присоединяется.
- Удаление (DELETE или `active=false`) деактивирует учётную запись, строка остаётся. Сеансы отзываются, API-ключи отключаются в том же шаге, в журнале аудита запись `scim.user.deactivate`. При повторной активации доступ возвращается, но API-ключи остаются выключенными и выпускаются заново.
- IdP никогда не присылает роль. Роль берётся только из группы, которую администратор сопоставил в интерфейсе. При нескольких группах действует высшая роль; после выхода из последней сопоставленной группы действует `OIDC_DEFAULT_ROLE`.
- Сопоставить группу с ролью **admin** можно только при `SCIM_ALLOW_ADMIN_GROUPS=true`. Последнего активного администратора через SCIM нельзя ни деактивировать, ни понизить.

## Обязательный единый вход

`SSO_ENFORCED_DOMAINS=firma.example,filial.example` заставляет вход по паролю, самостоятельную регистрацию и сброс пароля для этих доменов отвечать 403 `auth.sso_required`. Администратор с `metadata.break_glass = true` исключён, чтобы сбой IdP не заблокировал всех. Используйте вместе с `OIDC_ENABLED=true`, иначе сервер предупредит при запуске.

## Что поддерживается

Поддерживается: Users и Groups, GET/POST/PUT/PATCH/DELETE, `filter` с `eq` по `userName`, `externalId` (пользователи) и `displayName` (группы), постраничная выдача `startIndex` и `count` (не более 100), PatchOp `add`, `replace`, `remove`, включая объект значений Entra без пути.

Не поддерживается: SAML (поставьте перед системой мост SAML-в-OIDC на стороне IdP и используйте вход по OIDC), Bulk, ETag, сортировка, синхронизация паролей (`changePassword`), расширение enterprise, вложенные группы и другие операторы фильтра (ответ 400 `invalidFilter`).
