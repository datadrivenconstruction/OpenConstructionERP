# Единый вход: OIDC и SAML

Сотрудники входят через провайдера идентификации (IdP) компании вместо локального пароля. Оба протокола обслуживает один модуль `oe_sso`. Администратор настраивает одного или нескольких провайдеров для каждого тенанта в **Настройки > Единый вход**; на странице входа для каждого включённого провайдера есть своя кнопка. Переменные окружения для этого не нужны.

|  | OIDC | SAML 2.0 |
|---|---|---|
| Дополнительный пакет | нет | `pip install "openconstructionerp[saml]"` |
| Адрес возврата на вашем хосте | `/auth/oidc/callback` | ACS URL на карточке провайдера |
| Группы берутся из | claim `group_attribute` (по умолчанию `groups`) | атрибута `group_attribute` (по умолчанию `groups`) |

Секреты клиентов и сертификат IdP хранятся в базе данных, секреты в зашифрованном виде. Сохранённый секрет больше не показывается; оставьте поле пустым, чтобы сохранить его.

## Добавление провайдера

1. Войдите как администратор и откройте **Настройки > Единый вход**.
2. Нажмите **Добавить OpenID Connect** или **Добавить SAML 2.0**. SAML доступен, только если установлен дополнительный пакет (см. ниже).
3. Заполните поля, сохраните и зарегистрируйте адрес возврата в IdP.

Поля, общие для обоих протоколов:

| Поле | Значение |
|---|---|
| `display_name` (Название кнопки) | Текст на кнопке входа |
| `slug` (Краткое имя) | Часть URL, после создания не меняется |
| `email_domains` | Только эти почтовые домены могут входить через провайдера; пусто означает любые |
| `tenant_id` | Необязательный тенант провайдера |
| `group_attribute` | Claim или атрибут с группами или ролями (по умолчанию `groups`) |
| `group_role_map` | Имя группы (или идентификатор объекта группы Entra, или значение роли приложения) в роль, по строке `группа=роль` |
| `default_role` | Роль для новых людей вне сопоставленных групп (по умолчанию `viewer`) |
| `auto_create_users` | Создавать учётную запись при первом входе (по умолчанию включено) |
| `allow_admin_mapping` | Разрешить группе давать `admin` (по умолчанию выключено, иначе такое сопоставление отклоняется) |
| `link_by_email` | Привязывать вход к локальной учётной записи с тем же email (по умолчанию выключено) |
| `clock_skew_seconds` | Допустимое расхождение часов (по умолчанию 120) |
| `enabled` | Показывать кнопку на странице входа |

## OIDC

Дополнительные поля: `oidc_issuer` (URL эмитента), `oidc_client_id`, `oidc_client_secret`, `oidc_scopes` (по умолчанию `openid email profile`). В IdP зарегистрируйте redirect URI `https://<ваш-хост>/auth/oidc/callback`. Пошагово для Microsoft Entra ID: см. [install/azure.ru.md](install/azure.ru.md).

Установкам, которые раньше использовали переменные окружения `OIDC_*`, ничего делать не нужно: при первом запуске восстановление данных `sso_env_oidc_provider` один раз превращает их в запись провайдера (slug `oidc`, тот же redirect URI). После этого значения окружения игнорируются; меняйте или удаляйте запись в настройках.

## SAML 2.0

1. Установите дополнительный пакет на сервере: `pip install "openconstructionerp[saml]"` (он добавляет `signxml`, чистый Python, без системных библиотек) и перезапустите сервер. Без него вариант SAML скрыт в настройках; OIDC работает как раньше.
2. Добавьте провайдера SAML с `saml_idp_entity_id`, `saml_idp_sso_url` (привязка HTTP-Redirect), `saml_idp_cert` (сертификат подписи IdP, PEM) и при необходимости `saml_sp_entity_id`, `saml_email_attribute` (по умолчанию `email`) и `saml_name_attribute` (по умолчанию `displayName`).
3. Карточка провайдера показывает **ACS URL** (`https://<ваш-хост>/api/v1/sso/saml/<slug>/acs/`, привязка HTTP-POST), entity ID и **URL метаданных** (`https://<ваш-хост>/api/v1/sso/saml/<slug>/metadata/`). Передайте IdP URL метаданных или введите ACS URL и entity ID вручную.

По умолчанию вход начинается из приложения (SP-initiated): каждый ответ привязан к запросу, начатому в том же браузере, и может быть использован один раз. Повторный ответ отклоняется. Вход, начатый на стороне IdP, работает только при включённой опции провайдера `saml_allow_idp_initiated`.

## Как сопоставляются люди

Человек определяется парой (issuer, subject) провайдера, а не email. При первом входе:

- Если `link_by_email` выключено, создаётся новая учётная запись (при включённом `auto_create_users`); локальная запись с тем же email не затрагивается.
- Если `link_by_email` включено, привязывается существующая локальная запись с этим email. Для OIDC провайдер должен сообщать `email_verified`.
- Запись, уже привязанная к другому IdP, никогда не перепривязывается; вход завершается ошибкой `account_link_refused`.

## Сопоставление групп и ролей

`group_role_map` сопоставляет группы ролям, например `сметчики=editor`, `прорабы=manager`, `финансы=viewer`. Человек в нескольких сопоставленных группах получает наивысшую роль. Человек вне сопоставленных групп получает `default_role`. При выключенном `auto_create_users` войти могут только те, у кого уже есть учётная запись. Принудительный единый вход для целых почтовых доменов и автоматическое создание пользователей: см. [SCIM](scim.ru.md).

## Что видят пользователи при ошибке входа

Браузер возвращается на страницу входа с короткой надписью, без трассировки стека. Частые коды:

- `account_link_refused`: запись с этим email существует и привязана к другому провайдеру, либо `link_by_email` выключено.
- `account_not_found`: записи нет, а `auto_create_users` выключено. Администратор должен пригласить человека.
- `domain_not_allowed`: почтового домена нет в `email_domains` этого провайдера.
- `missing_claims`: IdP не прислал ни subject, ни email; проверьте имена атрибутов.
- `unsolicited`, `replayed`: ответ SAML не соответствует запросу, начатому в этом браузере, или уже использован. Начните заново со страницы входа.
- `saml_unavailable`: дополнительный пакет `[saml]` не установлен.
- Ошибки подписи SAML: неверный сертификат, расхождение часов или ACS URL, отличающийся от зарегистрированного. Сверьте карточку провайдера с IdP.
- Только OIDC: запрос входа устарел, провайдер недоступен или отклонил код входа.
