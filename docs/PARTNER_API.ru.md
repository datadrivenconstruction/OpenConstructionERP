# Partner API: ключи и вебхуки

Подключите OpenConstructionERP к вашей BI-, ERP- или бухгалтерской системе: через API-ключи с заданными правами и лимитами и через подписанные вебхуки, которые повторяются, пока не дойдут.

То же самое есть в интерактивной документации API под тегом **Partner API**. Ключи и адреса вебхуков настраиваются в приложении: **Настройки, Разработчикам**.

Языки: [English](PARTNER_API.md), [Deutsch](PARTNER_API.de.md), Русский.

## API-ключи

Передавайте ключ в заголовке `X-API-Key`:

```bash
curl -H "X-API-Key: oe_xxxxxxxx" https://your-server/api/v1/...
```

Ключ действует от имени владельца и никогда не получает больше прав. Его **области (scopes)** могут только сузить права роли владельца. Ключ без областей сохраняет все права владельца, поэтому давайте каждой интеграции минимально нужный набор. Имена областей совпадают с именами разрешений, например `boq.read`; полный список вашего сервера: `GET /api/v1/users/me/api-keys/scopes/`.

Ключи создаёт, ротирует и отзывает вошедший в систему пользователь:

| Запрос | Назначение |
| --- | --- |
| `GET /api/v1/users/me/api-keys/` | Список ваших ключей (секрет больше не показывается) |
| `POST /api/v1/users/me/api-keys/` | Создать ключ. Открытый текст только в этом ответе |
| `POST /api/v1/users/me/api-keys/{id}/rotate/` | Новый ключ с тем же именем, областями и лимитами. Старый работает ещё 24 часа |
| `DELETE /api/v1/users/me/api-keys/{id}` | Отозвать немедленно |

Параметры создания:

| Поле | Правило |
| --- | --- |
| `name` | Уникально среди ваших активных ключей |
| `permissions` | Имена областей из каталога |
| `expires_at` или `expires_in_days` | В будущем, не дальше 2 лет |
| `rate_limit_per_min` | От 1 до 6000. Если не указано, действует значение сервера |
| `allowed_cidrs` | До 20 сетей IPv4 или IPv6, например `203.0.113.0/24`. Если не указано, разрешён любой адрес |

У пользователя может быть 25 активных ключей. Сервер не пишет ключ в логи; в журнале аудита только идентификатор и видимый префикс.

### Ошибки и лимиты

| Статус | Значение |
| --- | --- |
| 401 | Ключ не передан, неизвестен, отозван или просрочен |
| 403 `api_key.ip_denied` | Адрес клиента вне `allowed_cidrs` |
| 403 | У ключа нет области, нужной маршруту |
| 429 `api_key.rate_limited` | Превышен минутный лимит ключа. Подождите `Retry-After` секунд |

В ответах на вызовы с ключом есть `X-RateLimit-Limit` и `X-RateLimit-Remaining`. За обратным прокси задайте `TRUSTED_PROXIES`, чтобы адрес клиента брался из `X-Forwarded-For` и не подделывался.

## Вебхуки

Адрес создаётся запросом `POST /api/v1/integrations/webhooks/`. URL должен быть `https` (обычный `http` только на сервере в режиме отладки) и вести на публичный адрес; он проверяется заново при каждой отправке, поэтому имя, которое позже указывает на внутренний адрес, будет отклонено. Можно задать `secret` не короче 24 символов; если его не указать, сервер сгенерирует его и один раз вернёт в `signing_secret`. На аккаунт можно создать 20 адресов.

Подписывайтесь на имена событий из `GET /api/v1/integrations/webhooks/events/` или на `*` для всех. `POST /api/v1/integrations/webhooks/{id}/test/` отправляет событие `ping`.

Каждая доставка это `POST` с JSON-телом и заголовками:

| Заголовок | Значение |
| --- | --- |
| `X-OE-Signature` | `t=<unix-секунды>,v1=<hex HMAC-SHA256>` |
| `X-OE-Event` | Имя события |
| `X-OE-Delivery` | Идентификатор доставки. Не меняется при повторах и повторной отправке: по нему убирайте дубли |
| `X-Webhook-Signature` | Устаревший: HMAC только от тела. Сохраняется два релиза, затем будет удалён. Переходите на `X-OE-Signature` |

Тело:

```json
{
  "event": "boq.position.created",
  "event_id": "…",
  "timestamp": "2026-11-03T12:00:00+00:00",
  "source_module": "oe_boq",
  "data": { "…": "…" }
}
```

### Проверка подписи

Подписывается строка: метка времени, точка и необработанное тело запроса. Отклоняйте метку времени, отличающуюся от ваших часов более чем на 5 минут, и сравнивайте за постоянное время.

Python:

```python
import hashlib, hmac, time

def verify(secret: str, header: str, body: bytes, tolerance: int = 300) -> bool:
    parts = dict(p.strip().split("=", 1) for p in header.split(","))
    t = int(parts["t"])
    if abs(time.time() - t) > tolerance:
        return False
    expected = hmac.new(secret.encode(), f"{t}.".encode() + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])
```

Node.js:

```js
const crypto = require("node:crypto");

function verify(secret, header, rawBody, tolerance = 300) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.trim().split("=")));
  const t = Number(parts.t);
  if (!Number.isFinite(t) || Math.abs(Date.now() / 1000 - t) > tolerance) return false;
  const expected = crypto.createHmac("sha256", secret).update(`${t}.`).update(rawBody).digest("hex");
  const given = Buffer.from(parts.v1 ?? "");
  const want = Buffer.from(expected);
  return given.length === want.length && crypto.timingSafeEqual(given, want);
}
```

`rawBody` должен быть теми же байтами, что пришли, до любого разбора JSON.

### Доставка и повторы

Отвечайте любым `2xx` в течение 10 секунд. Редиректы не выполняются.

| Результат | Что происходит |
| --- | --- |
| `2xx` | Доставлено |
| `408`, `429`, `5xx`, таймаут, ошибка соединения | Повтор через 1 минуту, 5 минут, 30 минут, 6 часов; после пятой неудачной отправки доставка получает статус `dead` |
| Любой другой `4xx`, `3xx`, заблокированный адрес | Сразу `dead`, без повторов |

Статусы доставки: `pending`, `retrying`, `delivered`, `dead`. Мёртвую доставку можно отправить снова запросом `POST /api/v1/integrations/webhooks/deliveries/{id}/redeliver/` (или кнопкой «Отправить снова» в Настройки, Разработчикам); расписание начнётся заново. Адрес отключается после 10 мёртвых доставок подряд.

## Совместимость

Контракт только расширяется. В рамках основной версии мы можем добавлять запросы, поля ответов, имена событий, области и заголовки; мы не переименовываем и не удаляем их и не меняем их смысл. Игнорируйте незнакомые поля и события. Публичный интерфейс `/api/public/v1` со своей версионируемой схемой планируется отдельным шагом.
